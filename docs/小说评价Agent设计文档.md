# Quill 小说评价 Agent v1 设计文档

## 1. 文档目标

本文档定义 Quill 小说评价 Agent v1 的设计方案。
该 Agent 用于对 AI 自动生成的小说内容进行结构化评审、量化打分、问题诊断与修订建议输出，并将评审结果反馈给生成流水线，形成"生成 → 评价 → 修订 → 再评价"的闭环。

v1 的目标不是模拟文学评论家，而是作为一个**面向创作系统的质量裁判与调度节点**，稳定判断当前内容是否达标、哪里有问题、应如何修订、是否允许进入下一阶段。

---

## 2. 设计目标

### 2.1 质量判断
判断当前生成内容是否达到最低可用标准，以及其整体质量处于什么水平。

### 2.2 问题诊断
识别生成文本中的问题类型，例如：
- 剧情推进不足
- 角色塑造扁平
- 设定冲突
- 节奏拖沓
- 语言模板化
- 明显 AI 味
- 与章节目标偏离

### 2.3 量化比较
对多个候选版本进行横向比较，支持 rerank、自动选择、版本淘汰。

### 2.4 修订指导
输出具体、可执行的修改建议，而不是泛泛而谈。

### 2.5 工作流决策
根据评分结果决定：
- 通过
- 局部重写
- 整章重写
- 转人工审阅
- 回退到上游重新规划

---

## 3. 适用范围

v1 主要服务于以下场景：
- AI 自动生成章节后的质量评审
- 多候选章节版本的排序与筛选
- 重写前的问题定位
- 重写后的结果复评
- 长篇小说持续生成过程中的质量守门

---

## 4. 核心设计原则

### 4.1 先 gate，后评分
先做硬性检查，再做细粒度评分。

### 4.2 分项评分优于单一总分
只给总分没有修订价值。必须输出分维度评分。

### 4.3 评价必须绑定上下文
评价 Agent 不能只看当前文本，必须参考章节目标、分卷目标、前文摘要、角色卡、设定卡。

### 4.4 评价结果必须可驱动后续动作
评分不是终点，输出必须能直接驱动重写 prompt 生成、问题路由、版本淘汰、人工介入。

### 4.5 先做稳定 v1，再做复杂多 agent
v1 追求稳定、可解释、易接入。

---

## 5. Agent 在 Quill 系统中的角色

整体链路：
```
规划 Agent
→ 分卷/章节卡生成
→ 正文生成 Agent
→ 小说评价 Agent
→ 决策器
   ├─ 通过 → 进入下一章
   ├─ 局部重写 → 修订 Agent
   ├─ 整章重写 → 重新生成
   └─ 人工审阅 → 作者工作台
```

其角色不是创作，而是**创作质量控制中枢**。

---

## 6. 输入设计

### 6.1 必要输入

| 输入 | 说明 |
|------|------|
| 当前正文 | 待评审的章节文本 |
| 章节卡 | 章节编号、标题、本章目标、关键事件、主要人物、结尾钩子 |
| 分卷信息 | 分卷标题、目标、核心冲突、当前章节位置 |
| 前文章节摘要 | 最近 1-3 章摘要 |
| 角色卡 | 角色姓名、身份、当前状态、人物目标、人物关系、角色声音 |
| 世界设定卡 | 世界观规则、时代背景、势力关系、特殊术语、禁止违背的设定约束 |

### 6.2 可选输入

| 输入 | 说明 |
|------|------|
| 项目风格约束 | 古风克制/偏悬疑/不要现代口语等 |
| 作者偏好 | 更重人物关系/弱化旁白总结等 |
| 候选版本列表 | 需要对多个版本 rerank 时输入 |

---

## 7. 输出设计

输出包括五层：
1. 硬性检查结果（Pass / Warn / Fail）
2. 分维度评分
3. 问题标签
4. 修订建议
5. 决策结果

---

## 8. v1 评分体系总览

总分 100 分，八个核心维度：

| 维度 | 分值 |
|------|------|
| 章节功能完成度 | 15 |
| 剧情推进与因果性 | 15 |
| 冲突与张力 | 15 |
| 人物塑造与角色声音 | 15 |
| 语言与文风质量 | 10 |
| 连贯性与一致性 | 10 |
| 信息控制与节奏 | 10 |
| 结尾钩子与续读意愿 | 10 |

---

## 9. 硬性检查（Gate Layer）

优先级高于普通评分。严重失败项应直接打回或转人工审阅。

### 9.1 检查项

| 检查项 | 说明 |
|--------|------|
| 文本完整性 | 输出中断/未完成句子/占位文本/明显残缺/大量重复段落 |
| 格式与可读性 | 乱码/异常符号污染/段落混乱/不可读输出 |
| 设定硬冲突 | 人名错乱/身份错乱/能力设定冲突/世界规则冲突/时间线矛盾 |
| 严重偏离章节目标 | 章节未完成应有任务/关键事件缺失/情节重心偏移 |
| 明显 AI 模板化 | 套话堆叠/强烈总结腔/反复同义表达/全章像梗概 |

### 9.2 Gate 层决策规则

若以下任一项 fail，默认不能直接通过：
- 文本完整性 fail
- 设定硬冲突 fail
- 严重偏离章节目标 fail
- 格式与可读性 fail

---

## 10. 八维评分细则

### 10.1 章节功能完成度（15 分）
判断本章是否完成了"它应该完成的任务"。

扣分信号：
- 写了很多但状态没有变化
- 主要内容只是重复前文
- 看似热闹但没完成章节职责

### 10.2 剧情推进与因果性（15 分）
判断故事是否真实向前发展，并具有合理因果链。

扣分信号：
- 为推进而推进
- 角色突然转变
- 关键线索来得过于方便
- 冲突轻易解决

### 10.3 冲突与张力（15 分）
判断本章是否有足够的压力、阻碍、风险与戏剧性。

扣分信号：
- 只有信息说明，没有场面冲突
- 角色轻易得到信息
- 全章平缓无压力

### 10.4 人物塑造与角色声音（15 分）
判断人物是否立得住，不同角色是否有辨识度。

扣分信号：
- 所有人说话像同一个人
- 对白只传信息
- 人物行为不符合角色逻辑
- 主角像被剧情拖着走

### 10.5 语言与文风质量（10 分）
判断文本语言是否顺畅，稳定、适配项目风格。

扣分信号：
- 大量"他沉默了""空气仿佛凝固"
- 过多抽象形容词
- 句式重复
- 解释腔过重

### 10.6 连贯性与一致性（10 分）
判断当前文本与既有上下文之间是否一致。

扣分信号：
- 前后设定打架
- 时空跳跃不交代
- 人物状态突变无原因
- 场景拼接感强

### 10.7 信息控制与节奏（10 分）
判断信息投放是否适量，节奏是否匹配章节任务。

扣分信号：
- 连续背景解释
- 同一信息反复讲
- 应该快时很慢，应该慢时很跳
- 没有有效的场景推进

### 10.8 结尾钩子与续读意愿（10 分）
判断章节结尾是否形成下一章驱动力。

扣分信号：
- 结尾泄气
- 只是总结，没有推进
- 没有新问题或情绪拉力

## 11. 问题标签体系

### 剧情类
- `weak_plot_progress`
- `causality_gap`
- `convenient_plot_device`
- `missing_key_event`

### 冲突类
- `low_tension`
- `weak_conflict`
- `stakes_too_low`

### 人物类
- `flat_character_voice`
- `character_out_of_role`
- `weak_protagonist_agency`
- `tool_like_supporting_cast`

### 语言风格类
- `ai_smell`
- `repetitive_expression`
- `expository_tone`
- `over_abstract_emotion`
- `weak_style_alignment`

### 连贯性类
- `continuity_error`
- `worldbuilding_conflict`
- `timeline_conflict`
- `abrupt_transition`

### 节奏类
- `pace_too_slow`
- `pace_too_fast`
- `info_dump`
- `underdeveloped_scene`

### 章节结构类
- `missing_hook`
- `chapter_goal_not_met`
- `chapter_flat_arc`

v1 建议输出 3-8 个最核心标签。

---

## 12. AI 味检测规则

### 12.1 检测点

#### 1. 套话密度
高频出现：仿佛/似乎/不由得/某种说不清的/空气仿佛凝固/心头一震/久久不语

#### 2. 句式重复
多句连续使用相似结构。

#### 3. 抽象情绪堆叠
只讲"复杂""压抑""悲伤"，不落到动作与细节。

#### 4. 总结腔 / 解释腔
不像小说在发生，而像旁白在概括。

#### 5. 功能性对白
人物只交换信息，不展现性格。

#### 6. 无效修辞
修辞很多，但不服务于场景或人物。

### 12.2 输出方式
- 作为 `ai_smell` 标签输出
- 给出严重度：low / medium / high
- 在严重时影响 Gate 层和语言维度评分

---

## 13. 评分汇总与最终决策

### 13.1 分数计算
总分 = 八个维度加总，满分 100

### 13.2 推荐阈值

| 总分 | 决策 |
|------|------|
| 90-100 | 通过 |
| 80-89 | 通过，但记录优化建议 |
| 70-79 | 局部重写 |
| 60-69 | 整章重写 |
| 0-59 | 打回上游重规划或人工介入 |

### 13.3 Gate 覆盖规则
若 Gate 出现严重 fail，总分不得直接触发"通过"。
优先级：`Gate fail > 总分高低`

---

## 14. 修订建议输出规范

### must_fix（必改项）
必须处理，否则不能进入下一阶段。

### should_improve（建议优化）
影响质量，但不一定阻塞工作流。

### optional_enhancements（可选增强）
提升可读性与风格层次。

## 16. Prompt 设计骨架

```
你是 Quill 小说评价 Agent。

你的任务不是做泛泛文学评论，而是对当前章节进行结构化质量评审，并给出可执行的修订建议。

你将收到以下输入：
1. 当前章节正文
2. 本章章节卡
3. 所属分卷信息
4. 前文章节摘要
5. 角色卡
6. 世界设定卡
7. 项目风格约束（可选）

请按以下顺序完成任务：

第一步：执行硬性检查
检查以下项目，并输出 pass / warn / fail 与理由：
- 文本完整性
- 格式与可读性
- 设定硬冲突
- 章节目标对齐度
- 明显 AI 模板化

第二步：执行八维评分

第三步：输出问题标签（3-8 个最关键的）

第四步：输出亮点与主要问题

第五步：输出修订建议
- must_fix
- should_improve
- optional_enhancements

第六步：输出最终决策
- pass / pass_with_notes / partial_rewrite / full_rewrite / human_review

请输出严格 JSON。
```

## 17. 在 Quill 中的接入方式

### 17.1 生成后立即评审
每次正文生成完成后，自动送入评价 Agent。

### 17.2 作为版本排序器
有多个生成候选时，对多个版本分别评分，按总分和 veto 规则排序。

### 17.3 作为重写路由器
根据标签决定送给哪类修订 Agent：
- `ai_smell` → 风格修订
- `continuity_error` → 一致性修订
- `chapter_goal_not_met` → 结构性重写
- `low_tension` → 冲突增强修订

### 17.4 作为作者工作台反馈层
将评分卡、问题标签和修订建议展示给作者，便于人机协作。

---

## 18. v1 边界与限制

1. **偏重"工程化创作质量"** - 更擅长判断结构、目标完成度、一致性，而不是纯文学气质高下
2. **对超长上下文仍受限** - 如果不给足摘要与角色卡，跨章一致性判断会下降
3. **审美判断存在主观性** - v1 更适合作为"质量守门 + 修改指导"，而不是绝对文学评判
4. **不应独自决定最终成书版本** - 高分不等于最打动人的版本，建议保留人工选择权

---

## 19. v2 演进方向

- **多 critic 架构** - 拆分为 Plot Critic / Character Critic / Style Critic / Continuity Critic / Judge Agent
- **分层评审** - 支持句段级/场景级/章节级/分卷级/全书级
- **风格对齐评分** - 增加"是否写成了项目想要的那种书"的维度
- **自动修订闭环** - 评审结果自动生成修订 prompt，触发重写 agent
- **长程记忆一致性检查** - 引入更强的角色状态追踪与设定数据库比对

---

## 20. MVP 定义

Quill 小说评价 Agent v1 的最小可用版本包含：
- 硬性检查 5 项
- 八维评分卡
- 问题标签输出
- 修订建议三层结构
- 最终决策字段
- JSON 结构化输出
- 接入章节生成后的自动评审链路
