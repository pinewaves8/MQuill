# 评分链修复计划

## 问题结论

当前章节评估分数存在三类硬伤，已经足以导致名著与普通 AI 文本出现接近分数，不能作为可靠质量判断依据：

1. 分数映射错位
   8 维原始评分使用的是 `0-15` / `0-10` 量表，但在落库和前端展示时直接当成了 `0-100` 使用，导致维度卡与总分被整体压缩到 0-20 左右。

2. 评分方向反转
   Critic Agent 的决策规则是“高分更好”，但前端文案和部分展示逻辑写成了“分数越低越好”，造成用户理解与系统决策相反。

3. 百分位是伪造值
   当前 `percentile` 由 `overall * 0.8 + Math.random() * 20` 生成，只是 mock 数据，没有任何统计意义。

## 修复目标

第一阶段先修三项硬伤，不改 Agent 的大框架：

1. 统一评分语义为“高分表示质量更高”
2. 将 8 维原始评分先归一化到 100 分制，再计算 6 维卡片与总分
3. 移除假 percentile 的误导性展示，改为“校准中”占位

## 实施步骤

### 1. 修正后端评分归一化

文件：
- `apps/web/src/app/api/agents/evaluate/[chapterId]/route.ts`

动作：
- 将 `0-15` 维度统一映射到 `0-100`
- 将 `0-10` 维度统一映射到 `0-100`
- `foreshadowRecovery` 继续保留为 0，待真实伏笔检测接入后再启用
- `ai_smell_severity` 改成两套值：
  - 风险分：用于展示模板化程度
  - 自然度分：`100 - 风险分`，用于参与整体质量加权

### 2. 修正前端卡片映射

文件：
- `apps/web/src/components/editor/evaluation-score-card.tsx`

动作：
- 与后端使用同一套 100 分制维度
- 总分颜色改为“高分更好”
- 普通维度颜色改为“高分更好”
- `AI模板化程度` 仍展示风险值，保留“越低越好”的专门说明
- 删除“评分越低表示质量越好”文案

### 3. 去掉伪 percentile

文件：
- `apps/web/src/app/api/agents/evaluate/[chapterId]/route.ts`
- `apps/web/src/components/editor/evaluation-score-card.tsx`

动作：
- 后端先不再生成随机 percentile，统一置为 `0`
- 前端当 `percentile <= 0` 时显示“百分位校准中”
- 后续接入真实样本库前，不再展示“超越 X% 的章节”

## 第二阶段建议

三项硬伤修完后，再做评估器校准：

1. 给 Critic Agent 补齐章节目标、关键事件、主要人物、前章摘要等上下文
2. 建一个小型标定集：
   - 名著章节
   - 优秀人工章节
   - 中等 AI 章节
   - 劣质 AI 章节
3. 以“排序正确”作为第一目标，而不是先追求绝对分数
4. 再决定 percentile 的真实计算方式

## 风险提示

当前 `critic-agent.ts` 存在明显乱码/编码污染现象，虽然不影响本阶段修复分数数学，但后续应尽快整理提示词源文件编码，否则会继续影响评估稳定性与可维护性。
